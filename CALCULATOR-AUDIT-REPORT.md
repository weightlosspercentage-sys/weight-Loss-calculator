## Summary
- **Site-wide category averages:** User Needs 7.6/10; expert guidance 5.0/10; Semantic SEO 7.1/10; clinical-review 7.3/10; Interlinking 8.5/10; Schema 7.9/10.
- **Overall:** 1,911 / 2,640 = **72.4%** (equivalent average 43.4/60).
- **Three lowest-scoring calculators:** `water-intake` 36/60; `bariatric-surgery-weight-loss` 37/60; `bmr` 39/60. `macro`, `dog-weight-loss`, `baby-weight-loss`, `glp1-weight-loss`, and `peptide-dosage` also scored 39/60.

## Live behavior findings
- 44/44 direct routes loaded HTTP 200; browser DOM inspection found controls on 42/44 pages (the two exceptions are called out below). Several legacy controls were outside `main` because the static pages embed calculator UI in a non-semantic wrapper.
- Interaction sampling across every route: food/fitness calculators with action buttons changed rendered output after input/action; multiple legacy/static pages produced `Unexpected token ';'` page errors and did not expose an actionable control inside `main` (`bmi`, `bmr`, `body-fat`, `calorie`, `dog-weight-loss`, `infant-weight-loss`, `keto`, `macro`, `newborn-weight-loss`, `peptide-dosage`, `postpartum-weight-loss`, `protein`, `tdee`, `water-intake`, `weight-loss`, plus related legacy pages). Treat this as a hydration/runtime defect requiring per-route verification.
- `bariatric-surgery-weight-loss` rendered with zero inputs/buttons and a 404 resource request: critical calculator availability issue despite HTTP 200.
- `water-intake` also rendered no controls in the page-level audit; `tdee` had no controls in the inspected `main` during the interaction pass. Confirm intended widget placement and bundle after fixing the shared runtime/parser path.
- Repeated console 403s were observed for blocked third-party/resource requests; these should be separated from first-party calculator failures during remediation.
